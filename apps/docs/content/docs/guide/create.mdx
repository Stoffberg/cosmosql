## Creating Documents

Creating documents in CosmosDB with CosmosQL is straightforward and fully type-safe. This guide covers single document creation, bulk operations, and best practices.

### Single Document Creation

The basic `create` operation inserts a new document into your container:

```typescript
const newUser = await db.users.create({
  data: {
    id: 'user_123',
    email: 'john@example.com',
    name: 'John Doe',
    age: 30,
    isActive: true,
    createdAt: new Date()
  }
});

// Type: User (fully typed result)
```

**Important:** All required fields from your schema must be provided. TypeScript will enforce this at compile time.

### Using Default Values

When your schema defines default values, you don't need to provide them explicitly:

```typescript
const user = await db.users.create({
  data: {
    id: 'user_124',
    email: 'jane@example.com',
    name: 'Jane Smith',
    age: 28,
    createdAt: new Date()
    // isActive uses default (true) - not required!
  }
});
```

CosmosQL automatically applies default values based on your schema definition.

### Bulk Create Operations

For creating multiple documents efficiently, use `createMany`:

```typescript
// All documents MUST share the same partition key
await db.posts.createMany({
  data: [
    { id: 'post_1', userId: 'user_123', title: 'First Post', content: '...' },
    { id: 'post_2', userId: 'user_123', title: 'Second Post', content: '...' },
    { id: 'post_3', userId: 'user_123', title: 'Third Post', content: '...' }
  ],
  partitionKey: 'user_123' // Required: ensures all docs are in same partition
});
```

<Callout type="warning" title="Same Partition Requirement">

CosmosDB batch operations only work within a single partition. If you attempt to create documents with different partition keys, CosmosQL will prevent this at the type level.

**Why?** CosmosDB's transactional batch API requires all operations to target the same partition key. This is a fundamental architectural constraint of CosmosDB, not a limitation of CosmosQL.

</Callout>

### Best Practices

**1. Always Provide IDs Explicitly**

```typescript
// ✅ Good: Explicit ID
const user = await db.users.create({
  data: {
    id: `user_${Date.now()}`, // Explicit and predictable
    email: 'user@example.com',
    // ...
  }
});

// ⚠️ Avoid: Relying on auto-generation
// CosmosDB doesn't have built-in auto-increment IDs like traditional SQL databases
```

**2. Use Meaningful IDs**

Choose IDs that make sense for your application:

```typescript
// ✅ Good: Human-readable IDs
'user_john@example.com'
'order_2024-01-15-abc123'
'post_user123_date456'

// ❌ Bad: Random UUIDs (unless you specifically need them)
'a3f5b8c2-d4e6-7890-abcd-ef1234567890'
```

**3. Set Timestamps Explicitly**

```typescript
const user = await db.users.create({
  data: {
    id: 'user_123',
    email: 'john@example.com',
    createdAt: new Date(), // Server time
    updatedAt: new Date()
  }
});
```

**4. Validate Data Before Creating**

While CosmosQL provides type safety, consider validating data at runtime:

```typescript
// Basic validation example
function validateUser(data: { email: string; age: number }) {
  if (!data.email.includes('@')) {
    throw new Error('Invalid email');
  }
  if (data.age < 0 || data.age > 150) {
    throw new Error('Invalid age');
  }
}

const user = await db.users.create({
  data: {
    id: 'user_123',
    ...validateUser(data), // Validate before creating
    createdAt: new Date()
  }
});
```

### Common Patterns

**Pattern: Multi-Tenant Applications**

```typescript
// For multi-tenant apps, use tenant ID as partition key
const posts = container('posts', {
  id: field.string(),
  tenantId: field.string(),
  title: field.string(),
  // ...
}).partitionKey('tenantId');

// Create posts scoped to a specific tenant
await db.posts.createMany({
  data: [
    { id: 'post_1', tenantId: 'tenant_abc', title: '...' },
    { id: 'post_2', tenantId: 'tenant_abc', title: '...' }
  ],
  partitionKey: 'tenant_abc'
});
```

**Pattern: Hierarchical Data**

```typescript
// Create parent-child relationships
const category = await db.categories.create({
  data: {
    id: 'cat_tech',
    name: 'Technology',
    parentId: null,
    createdAt: new Date()
  }
});

const subcategory = await db.categories.create({
  data: {
    id: 'cat_tech_ai',
    name: 'Artificial Intelligence',
    parentId: 'cat_tech', // Reference parent
    createdAt: new Date()
  }
});
```

### Error Handling

```typescript
try {
  const user = await db.users.create({
    data: {
      id: 'user_123',
      email: 'john@example.com',
      // ...
    }
  });
} catch (error) {
  if (error.code === 409) {
    // Document with this ID already exists
    console.error('User already exists');
  } else if (error.code === 429) {
    // Rate limit exceeded - too many requests
    console.error('Rate limit exceeded, please retry');
  } else {
    console.error('Failed to create user:', error);
  }
}
```
